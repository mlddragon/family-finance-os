## Canonical boundary

| Subject | Canonical home |
|---|---|
| Product requirements, technical design, code, tests, security and data-handling policy, implementation detail, release state, and repository history | This GitHub repository and its refreshed local checkout |
| Family-project identity, ownership and open-source classification, high-level status and decisions, commercialization, organizational placement, and cross-project routing | Mason's private Notion knowledge system |
| Real household financial data, generated reports, databases, logs, credentials, and runtime artifacts | The approved external `DATA_ROOT` or other owner-approved private runtime system; never git |
| Temporary analysis, brainstorming, and execution context | Chat; non-authoritative until written back to the canonical home |
| Migration history | The Notion Migration Register or a repository migration record; provenance only, not current authority |

Repository visibility, licensing, a knowledge hierarchy, or a newer timestamp does not by itself establish legal ownership, organizational placement, or current direction.

## Interpreting Notion state

- **Approved** — owner-accepted within the record's stated scope.
- **Working** — active and useful, but provisional or carrying open questions.
- **Exploring** — under consideration, not a commitment.
- **Source Context** — evidence or provenance, not a decision by itself.
- **Superseded** — retained for history and no longer current direction.

Status, scope, and canonical subject matter must be read together. Timestamps alone do not determine authority.
